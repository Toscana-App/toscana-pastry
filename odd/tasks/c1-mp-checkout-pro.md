# C1-MP — Webhook real + integración Mercado Pago + Checkout Pro (backend)

Objetivo: reemplazar `MockCheckoutProvider` por Mercado Pago real (Checkout Pro, MLA). Branch: `feat/c1-mercadopago-payments` (worktree `.worktrees/c1mp`). Delivery: `ask-on-risk`. Runner: `backend/.venv` de la raíz → `python -m pytest -q` desde `backend/`.

## Specs

- **S1 — Webhook real.** Pedido del usuario: "Una vez tengas la impleemntacion para webhook y la integracion". `POST /api/v1/webhooks/mercadopago` valida la firma oficial de Mercado Pago: header `x-signature` = `ts=...,v1=...`, `v1` = HMAC-SHA256 hex de `id:{data.id};request-id:{x-request-id};ts:{ts};` con el secreto del webhook; comparación en tiempo constante. Firma inválida/ausente → 401. Body = notificación MP `{"type": "...", "data": {"id": "..."}}`. `type != "payment"` → 200 sin efecto. Para `payment`: consulta el pago al proveedor (estado + `external_reference` = id del pedido) y aplica la máquina de estados existente de C1.6 (approved una sola vez, pending nunca pisa terminal, rejected/failed nunca revierten `paid`, cash queda `paid=false`). Con firma válida → 200 `{"ok": true}`.
- **S2 — Dedupe por (pago, estado).** MP notifica varias veces el mismo `data.id` con estados distintos. Dedupe = mismo pago + mismo estado → 200 sin efecto; mismo pago con estado nuevo → se aplica. (Requiere quitar el `unique` de `payment_events.provider_payment_id`; la clave pasa a ser el `id` del evento `"{payment_id}:{status}"`.)
- **S3 — Integración (adapter).** `MercadoPagoCheckoutProvider` (capa `data`, I/O async con `httpx`, sin SDK) implementa `CheckoutProvider`: `create_payment` crea una preferencia Checkout Pro (`POST /checkout/preferences`) con `external_reference` = id del pedido y devuelve `{reference: preference_id, checkout_url}`; `get_payment` lee `GET /v1/payments/{id}` y mapea estados MP → `pending|approved|rejected|failed` + devuelve el id del pedido.
- **S4 — Checkout Pro reemplazando el mock.** Pedido del usuario: "implementa el checkout pro reemplazando el mock". `POST /orders/{id}/payment` usa el provider real con el monto real del pedido (total de ítems − `discount_amount`), no `0.0`. `MockCheckoutProvider` se elimina del código de runtime. Sin credenciales configuradas → 503 `payment_provider_unavailable`. Config por env: `MP_ACCESS_TOKEN`, `MP_WEBHOOK_SECRET`, opcionales `MP_NOTIFICATION_URL`, `MP_BACK_URL`.
- **S6 — El cliente paga su pedido.** Pedido del usuario (L7): "implementa las modificaciones que estaban fuera del pedido". `POST` y `GET /orders/{id}/payment` dejan de exigir `require_admin`: los puede usar el dueño del pedido (`order.customer_id == user.id`) o un admin; otro cliente → 404 anti-sondeo (C1.4).
- **S7 — Idempotency-Key persistida (C1.4).** Misma key para el mismo pedido → misma respuesta guardada (200), sin crear otra preferencia. Otra key con `payment_status=pending` → 409 `payment_in_progress`. Estado terminal (`approved|rejected|failed`, o pedido ya pagado) → 422 `payment_finalized`. Se guarda en tabla nueva `payment_attempts` (la crea `create_all` también en DBs existentes).
- **S8 — `backend/pyproject.toml` declara dependencias.** Se reemplaza el stub poetry por el `pyproject.toml` + `uv.lock` commiteados en `feat/integrate-all-prs` (mismo driver SQLite/aiosqlite, incluye `httpx`).
- **S5 — Sin regresiones.** Suite verde salvo la falla preexistente `test_whatsapp_sends_api.py::test_resend_budget_exceeded_is_429`. Sin secretos en el repo.
